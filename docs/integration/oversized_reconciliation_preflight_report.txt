2. NEW FAILURE PATTERN
----------------------
The general failure was runaway PDF single-newline reconciliation. Once a
short structural cell seeded a merged unit, the accumulated left side became
prose-like. The former rule then appended every following short table/list
cell because it tested only the accumulated left side. A related lexical rule
could also cross blank-line paragraph boundaries before examining newline
structure.

3. GENERAL FIX
--------------
PDF single-newline prose reconciliation now requires both sides to be
prose-like unless a narrower existing continuation signal applies. A short
heading/label now attaches only to following prose. Lexical continuation may
cross continuous whitespace or one extraction newline, but not an arbitrary
blank-line paragraph boundary. Dedicated deterministic handling remains for
page labels, source captions, spaced-capital headings, country-code numeric
tables, legal recital starts, numbered tails, and footnotes.

No document ID or source-specific branch was added. The encoder, tokenizer
semantics, chunk target, overlap, and frozen 510-token content limit are
unchanged.

4. PREFLIGHT DESIGN
-------------------
scripts/preflight_corrected_sentence_units.py reads the accepted
documentos.jsonl and stops after format-aware source preparation, language
detection, bounded PySBD segmentation, corrected reconciliation, and token
safety classification. It does not pack production chunks, create manifests,
load an encoder, generate embeddings, load FAISS, or run retrieval.

The cheap prefilter uses NFKC-normalized UTF-8 byte length plus a conservative
SentencePiece margin. Only plausible candidates are exactly counted with the
frozen intfloat/multilingual-e5-small tokenizer. Exact counts, not the cheap
prefilter, determine acceptance.
