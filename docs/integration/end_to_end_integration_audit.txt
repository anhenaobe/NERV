1. EXECUTIVE SUMMARY
====================

FINAL VERDICT: END_TO_END_NOT_READY.

FACT FROM CODE: The checkout contains two distinct project layouts:

  A. C:\dev\NERV is a production ingestion project. Its executable implementation
     is src/lector_corpus.py and it writes data/processed/documentos.jsonl plus
     data/processed/errores.jsonl.

  B. C:\dev\NERV\NERV is a separately packaged semantic retrieval project. It
     contains chunking, embeddings, FAISS, retrieval, ranking, evaluation, and
     manual integration scripts, but its own ingestion and preprocessing modules
     are NotImplementedError placeholders.

FACT FROM CODE: There is no single callable path from the outer ingestion CLI to
the nested semantic pipeline. The nested project has no corpus/, outputs/, or
usable production config files in this checkout. Its config/encoder_config.json
and config/config.yaml are absent.

FACT FROM CODE: The outer documentos.jsonl schema is directly accepted by the
nested chunking reader. This is the strongest currently compatible boundary.

FACT FROM CODE: The nested chunking implementation emits the eight-field base
chunk record doc_id, chunk_id, fuente, formato, fenomeno, posicion, num_tokens,
texto. No hard-split fields or hard-split implementation exist in this checkout.
The user-provided validated counts and SHA-256 therefore describe an artifact or
revision that is not present here and cannot be re-established from current code.

FACT FROM CODE: Embedding generation, IndexFlatIP retrieval, query prefixing,
max-pooling document aggregation, and official result-shape validation have real
implementations. They are connected only by scripts and positional assumptions.

FACT FROM CODE: Encoder execution conflicts with the expected frozen contract:
load_encoder forces max_seq_length=256, while the requested hard encoder limit is
512. SentenceTransformer tokenization is not configured with
add_special_tokens=false or a tokenizer revision. Any chunk longer than the
effective 256-token model limit can be truncated during embedding generation.

INFERENCE: A physical embedding job could be attempted after installing packages
and supplying artifacts, but it would not be a contract-correct full-corpus run.
The current code cannot safely claim that every one of 336239 vectors represents
the full validated chunk text.

RECOMMENDATION: First reconcile the checkout and frozen encoder contract, add a
small manifest-backed chunk-to-embedding adapter, and prove a tiny end-to-end
fixture before introducing a thin orchestrator.


2. FINAL VERDICT
================

Verdict: END_TO_END_NOT_READY

Why:

  1. No current end-to-end command joins outer ingestion and nested retrieval.
  2. NERV/config/encoder_config.json is missing and blocks chunking CLI parsing.
  3. pysbd is imported by chunking but absent from NERV/requirements.txt.
  4. NERV/config/config.yaml is missing; config.example.yaml contains the
     placeholder encoder example/model-name.
  5. No real corpus, documentos.jsonl, chunks.jsonl, queries, embeddings,
     metadata, or FAISS index exists in this checkout.
  6. The embedding encoder forces 256 tokens, conflicting with the requested
     512-token hard encoder limit.
  7. External embeddings are aligned to chunks only by row count and assumed
     order; there is no chunk hash/ID manifest at that boundary.
  8. The only broad integration paths are manual scripts, not a production
     orchestrator with stage contracts and safe reuse.

Smallest path to a first working run:

  a. Establish one real project root and make the outer ingestion output an
     explicit input to the packaged NERV project.
  b. Restore/create the authoritative encoder_config.json from an approved
     frozen contract and make embeddings consume the same values.
  c. Declare pysbd and create a real config.yaml without placeholder values.
  d. Resolve the 256-versus-512 encoder limit and special-token policy.
  e. Add a streaming chunks-to-embeddings adapter that writes float32 vectors
     and an alignment manifest containing ordered chunk IDs and source hash.
  f. Build/load IndexFlatIP only after validating dimension, finite values,
     normalization, row count, and manifest identity.
  g. Run a small fixture end to end; only then run the full corpus.

7. INGESTION CONTRACT
=====================

Producer: outer src/lector_corpus.py::_registrar_resultado_procesamiento.
File type: UTF-8 JSON Lines, one object per line.

Required fields produced:
  doc_id     String "DOC-" plus first 12 hex characters of SHA-256.
  fuente     POSIX relative path from corpus root.
  formato    pdf, html, txt, md, json, csv, xlsx, imagen, or pbf.
  fenomeno   Integer 1, 2, or 3 derived from an F1_/F2_/F3_ path component.
  idioma     es, en, pt, or desconocido from a lightweight detector.
  texto      Cleaned non-empty string.

Optional field:
  metadata   Object. JSON may contribute metadata.procedencia.urls; images may
             contribute technical image metadata.

doc_id generation:
  Default fast mode hashes lowercased relative path, file size, and mtime_ns.
  --doc-id-contenido hashes lowercased relative path plus complete bytes.
  Therefore default doc_id is reproducible only while mtime is preserved; moving
  or touching a file can change it without changing extracted content.

Ordering:
  Source files are discovered with sorted(corpus.rglob("*")). Parallel results
  are registered in task order. OCR merge fusion is sorted by fuente. Output is
  therefore intended to be deterministic for the same inputs, metadata, and mode.

Error behavior:
  Unsupported/auxiliary files, empty content, OCR-pending files, and failures are
  written to errores.jsonl and not documentos.jsonl. An unrecognized phenomenon
  is a per-file failure. Main exits for missing/invalid corpus directory.

Chunk consumer compatibility:
  NERV/src/nerv/chunking/pipeline.py::_REQUIRED_FIELDS requires exactly the five
  shared fields doc_id, fuente, formato, fenomeno, texto. idioma and metadata are
  accepted as extra input fields but discarded from chunk output.

Boundary classification: COMPATIBLE.
Hidden transformation: idioma and metadata are silently dropped by
build_chunk_record. No field renaming is required.


8. CHUNKING CONTRACT
====================

Producer: NERV/src/nerv/chunking/pipeline.py::build_chunk_record.
File type: compact UTF-8 JSON Lines, one chunk per line.

Base fields:
  doc_id       Copied from input document.
  chunk_id     "{doc_id}-chunk-{position:04d}".
  fuente       Copied from input.
  formato      Copied from input.
  fenomeno     Copied from input.
  posicion     Zero-based integer enumeration within each document.
  num_tokens   Token count of "passage: " plus chunk text with special tokens off.
  texto        Chunk text without stored passage prefix.

Optional hard-split metadata:
  FACT FROM CODE: None is produced or consumed in the current checkout.
  No hard_split_source_unit_count, hard_split_generated_chunk_count, parent unit
  ID, split index, or equivalent field appears in current source.

Oversized sentence behavior:
  create_chunks emits a sentence larger than max_tokens unchanged as a standalone
  chunk. It does not hard-split it. pipeline records it as oversized.

Ordering:
  Document input order is preserved, and chunks are emitted in ascending position.
  IDs are deterministic for stable doc_id, text segmentation, and configuration.

Configuration:
  Intended canonical source is config/encoder_config.json through
  load_encoder_config. That file is absent. CLI flags can override model and token
  limits only after parse_args first successfully loads the missing file.

FACT FROM CODE: The current base output schema is directly accepted by the manual
embedding scripts because they load arbitrary JSON objects and use only texto,
doc_id, and chunk_id later.


9. EMBEDDINGS CONTRACT
======================

Direct answers:

1. Does embeddings load chunks.jsonl directly?
   NO. NERV/src/nerv/embeddings has no JSONL loader. Manual scripts load it.

2. Which fields does it expect?
   generate_embeddings expects only a sequence of already prepared strings.
   generador_con_tiempos expects chunk["texto"] for encoding and doc_id/chunk_id/
   texto for result recovery. paso_final_local expects complete chunks for metadata.

3. Does it tolerate optional hard-split fields?
   YES at the script loader level: unknown JSON fields remain in each dict and do
   not affect encoding. There is no validation of their semantics.

4. Does it preserve chunk order?
   YES in the current sequential list/batch loops. cargar_chunks appends file order;
   batch slices write results back to the same row interval.

5. How is chunk_id associated with embedding row i?
   Only by the assumption that chunks list row i produced embedding row i. The
   embedding file itself stores no chunk_id.

6. Is metadata discarded?
   generate_embeddings discards all metadata because it sees only strings.
   paso_final_local separately writes original chunk dictionaries to metadata.jsonl.
   generador_con_tiempos does not persist index metadata at all.

7. Is passage prefix applied exactly once?
   In generador_con_tiempos and prueba_rapida, yes for ordinary unprefixed texto:
   each script explicitly constructs "passage: " + texto once. The embeddings API
   does not own or check prefixing, so callers can omit it or double-prefix it.

8. Is truncation used?
   YES in effect. load_encoder sets SentenceTransformer.max_seq_length=256;
   SentenceTransformer encoding truncates inputs beyond that effective length.

9. Can it safely assume all chunks <=512?
   It does not validate num_tokens or text tokenization before encoding. Even if all
   chunks are <=512 under the chunk counter, the encoder currently caps at 256.

10. Does tokenizer/model configuration match config/encoder_config.json?
    UNKNOWN/NO. The file is absent. Against the expected contract in the audit
    brief, model name and L2 normalization match in hard-coded script paths, but
    max input length, explicit special-token behavior, tokenizer revision, device,
    and authoritative configuration do not match or are not controlled.

Output behavior:
  SentenceTransformer.encode returns a numpy array, normally float32 for this
  model; generate_embeddings immediately converts it to nested Python lists.
  generador_con_tiempos copies those values into a preallocated float32 array.
  Shape is expected to be (number of texts, 384) but generate_embeddings itself
  does not validate dimension or row count.

Streaming/memory:
  Not streaming. All chunks are loaded into memory. The checkpoint implementation
  allocates the complete float32 matrix. At 336239 x 384 x 4 bytes, the raw matrix
  is approximately 516 MiB, excluding chunk dictionaries, strings, model, batches,
  and temporary arrays. Each checkpoint saves the full allocated matrix.

Lifecycle/device:
  Model/tokenizer are loaded once inside SentenceTransformer. Scripts load one model
  per process. Default device is cpu. No embedding CLI offers --device or automatic
  CUDA selection.

Checkpoint/resume:
  generador_con_tiempos has a .npy plus .progreso.txt mechanism. It validates only
  that progress is in range. It does not verify source chunks hash, ordered IDs,
  model, dimension, prefix policy, or configuration before resuming.

Error handling/determinism:
  Errors propagate. There is no atomic checkpoint publication, recovery validation,
  or explicit deterministic torch setting. Model inference should normally be
  stable in evaluation mode, but strict reproducibility is UNKNOWN without pinned
  versions/revision and runtime execution.

Can current code generate contract-correct embeddings for all 336239 chunks without
modification? NO.

Blocking reasons: missing artifacts/dependencies, 256-token truncation against a
512-token hard contract, absent canonical config/revision, and unverified resume/
row-alignment identity. The loop can physically iterate that many records, but that
is not sufficient for a correct production artifact.

11. FAISS CONTRACT
==================

Index type: faiss.IndexFlatIP, confirmed in build_index.
Input dtype: converted to numpy float32.
Input shape: required 2D; second dimension required to be exactly 384.
Normalization: assumed, not performed or checked by build_index.
Metric API: caller must pass the string "cosine"; implementation then uses inner
product on the assumption of L2-normalized vectors.
IDs: implicit contiguous FAISS row positions 0..n-1. No IndexIDMap or chunk IDs.
Metadata: separate JSONL whose row i must match vector row i.
Save/load: faiss.write_index and faiss.read_index at caller-supplied paths.
Query: float32 (1, d) search; dimension mismatch is left to FAISS.

FACT FROM CODE: Embeddings generated by generate_embeddings are normalized before
insertion when the normal path is followed.

FACT FROM CODE: build_index accepts arbitrary callers and neither normalizes nor
verifies vector norms/finite values. Externally supplied .npy files can therefore
violate cosine semantics silently.

Alignment risk: HIGH. paso_final_local checks only embeddings.shape[0] equals the
number of loaded chunks, then writes metadata in current chunks order. A reordered
chunks file with the same row count passes and yields incorrect chunk recovery.


12. QUERY PATH
==============

Input source: caller-supplied queries.jsonl, conventionally
NERV/corpus/queries/queries.jsonl. That directory/file is absent.

Expected fields:
  query_id   Required by most scripts. generador.py can synthesize qNNN if absent.
  text       Preferred query text field.
  query      Accepted fallback query text field.

No shared validated query loader exists; each script duplicates a permissive JSONL
loader. Blank lines are skipped; JSON objects, uniqueness, order, and exact count
are validated only indirectly at final validate_results.

Encoding:
  encode_query rejects empty/whitespace text, applies "query: " exactly once, and
  uses generate_embeddings with batch size 1 and L2 normalization.

Top-k search:
  Retrieval scripts typically request 50 raw candidates. Final ranking keeps 10
  fragments and 3 documents. config.example.yaml says retrieval top_k=10, but
  generador.py ignores that value and uses CANDIDATE_POOL_SIZE=50.

Question/corpus separation:
  FACT FROM CODE: Queries are loaded from a separate query artifact and are never
  deliberately inserted into the document index.
  FACT FROM CODE: Outer ingestion excludes extracto_preguntas_50_v2.pdf only when
  it appears as a recognized auxiliary at the corpus root. The contamination
  filter can remove chunks containing exact normalized official query text and one
  known excluded source.
  INFERENCE: Leakage remains possible if question material appears under another
  filename/path or is paraphrased enough to evade literal/marker filters.


13. RETRIEVAL/RANKING
=====================

query_encoder.py:
  Prefix: query: 
  Batch: 1
  Normalization: L2 through generate_embeddings
  Validation: rejects empty query only

retriever.py:
  Input: one vector, index, positive top_k
  Output: ordered list of (integer row position, float inner-product score)
  Behavior: removes FAISS -1 padding positions

ranking.py:
  rank_results sorts descending by candidate["score"].
  deduplicate_by_chunk retains the highest-scoring occurrence per chunk_id.
  aggregate_scores_by_document uses max pooling, not CombSUM.

No learned reranker exists. No diversity policy exists. No document deduplication
is needed after max-pooling because output is keyed by doc_id. Score ties rely on
Python stable ordering and upstream candidate order.

Completeness: The components form a callable retrieval chain only when supplied an
already loaded encoder, already built index, and correctly aligned metadata. They
do not form a complete ingestion-to-retrieval system.

22. BLOCKING ISSUES
===================

BLOCKING-1: Split project roots and no complete orchestrator.
Evidence: outer src/lector_corpus.py is production ingestion; nested
NERV/src/nerv/ingestion is placeholder; NERV/generador.py starts from a prebuilt
index. No code calls all stages.
Impact: no single authoritative E2E execution path.
Smallest safe fix: define one thin orchestrator at the nested project root that
invokes outer ingestion by explicit adapter/import or first consolidate packaging.

BLOCKING-2: Missing NERV/config/encoder_config.json.
Evidence: configuration.py default points there; pipeline.parse_args calls it
before parsing overrides.
Impact: chunking CLI cannot start, even with explicit --encoder-model.
Smallest safe fix: restore the approved frozen file and validate it at startup.

BLOCKING-3: Missing declared pysbd dependency.
Evidence: sentence_splitter.py imports pysbd unconditionally; requirements omits it.
Impact: clean installation cannot import chunking.
Smallest safe fix: declare a compatible version and validate clean install.

BLOCKING-4: Required real artifacts are absent.
Evidence: no current raw corpus, documentos, production chunks, queries, embeddings,
metadata, or FAISS index; only a 31-row test chunk fixture exists.
Impact: no current E2E run can be attempted.
Smallest safe fix: identify approved external inputs and their hashes; do not
regenerate until contracts are fixed.

BLOCKING-5: Encoder hard limit conflicts with requested contract.
Evidence: embeddings/encoder.py forces MAX_SEQ_LENGTH=256; requested hard limit is
512 and current chunking can emit oversized complete sentences.
Impact: silent semantic truncation and token-count/embedding disagreement.
Smallest safe fix: decide and encode one authoritative max length/policy, then add
boundary tests for 256, 257, and 512-token inputs.

BLOCKING-6: Embedding row identity is not persisted or verified.
Evidence: .npy has no IDs; paso_final_local checks row count only; checkpoints have
only numeric progress.
Impact: same-length reordered/stale chunks silently map search hits to wrong text.
Smallest safe fix: ordered chunk-ID hash plus source SHA-256/model contract manifest,
verified before resume/index build.

BLOCKING-7: Missing runtime config and placeholder example values.
Evidence: generador.py requires config/config.yaml; it is absent. Example encoder is
example/model-name and index path uses encoder_example.
Impact: master retrieval command cannot start correctly after clone.
Smallest safe fix: create an approved real runtime config derived from the canonical
semantic contract, without duplicating frozen values unnecessarily.

BLOCKING-8: No contract-correct full embedding producer.
Evidence: embedding library accepts strings only; manual script loads all data,
hard-codes CPU/256 semantics, and checkpoint identity is unsafe.
Impact: cannot safely produce the input required by index construction for the full
validated corpus.
Smallest safe fix: a small streaming/batched adapter with device option, atomic
artifacts, manifest, resume verification, and shared configuration.

Number of blocking issues: 8.


23. IMPORTANT ISSUES
====================

IMPORTANT-1: build_index assumes vectors are normalized and finite; it does not
normalize or validate norms/NaN/Inf.

IMPORTANT-2: Chunking discards idioma and metadata. This may be acceptable for
retrieval, but it is an undocumented cross-stage loss of provenance.

IMPORTANT-3: Chunking current source has no hard split; complete sentences over the
configured limit remain oversized. This conflicts with the supplied validated
hard-split context and suggests checkout/artifact drift.

IMPORTANT-4: Default doc_id fast mode includes mtime_ns. Cloning/copying raw inputs
without preserved timestamps can alter IDs and invalidate downstream artifacts.

IMPORTANT-5: Model/tokenizer/library versions are unpinned. The tokenizer revision
is supported only by chunk counting, not embedding loading.

IMPORTANT-6: Tests for embeddings and FAISS are stale and expect NotImplementedError.
They will fail against current implementations and provide no positive contract
coverage for normalization, dimension, persistence, or row mapping.

IMPORTANT-7: config.example retrieval top_k=10 is ignored by generador.py, which
hard-codes candidate pool 50, fragment top 10, and document top 3.

IMPORTANT-8: Query JSONL has no dedicated schema validation before expensive model
or index work. Duplicate/out-of-order IDs fail only at final result validation.

IMPORTANT-9: Checkpoint writes the entire allocated vector array every 20000 rows,
including unfilled zero rows, and is not atomic.

IMPORTANT-10: External Colab embedding flow is referenced but its notebook and
artifact semantic contract are absent.

26. PROPOSED MINIMAL ORCHESTRATOR
================================

Recommended location: NERV/src/nerv/pipeline.py
Recommended CLI: python -m nerv.pipeline

Why this location:
  It belongs to the installed application package, can reuse typed stage functions,
  is testable without subprocesses, and avoids making a root script the source of
  truth. NERV/generador.py can remain an official delivery wrapper that calls the
  retrieval-to-results portion later.

Minimal responsibilities:

  load frozen semantic config and runtime config
  validate project/artifact paths
  run or reuse ingestion adapter output
  run or reuse validated chunks
  generate or reuse verified embeddings plus manifest
  build or load verified IndexFlatIP plus aligned metadata
  load and validate separate queries
  encode queries
  retrieve/rank
  validate and atomically save results
  atomically save run metrics/manifest

The orchestrator should sequence existing functions and thin adapters. It should
not contain document parsing, chunking logic, model math, FAISS ranking logic, or
evaluation metric implementations.

Error model:
  Fail fast before a stage on missing/mismatched contracts. Preserve prior valid
  artifacts via temporary-file plus atomic replace. Do not catch and continue after
  semantic config, manifest, dimension, or alignment failures.
